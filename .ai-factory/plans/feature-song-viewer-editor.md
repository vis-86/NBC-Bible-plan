# Song viewer/editor — autonomous implementation plan

Источник требований: `docs/song-viewer-spec.md` (§0–§10). Ветка: `chordpro-viewer`. Каждый запуск (в т.ч. автономный, из cloud routine) начинает с чистого чекаута — **этот файл единственный источник прогресса**, обновляй его перед завершением сессии.

## Правила для автономного агента

- Работай ТОЛЬКО в ветке `chordpro-viewer`. Никогда не трогай `main`, `deploy/`, прод-конфиги, `.env*`.
- Перед выходом: `npm run test` + `npm run lint` зелёные. Если тронут offline/SW/роутинг — обязателен `npm run build` → просмотр `out/sw.js` → `npm run e2e:offline` (см. `CLAUDE.md`).
- `.env.test` в git не попадает (gitignored). Если файла нет — создай его с фиктивными значениями по списку из `ENV_SETUP.md` (обязательные: `NEXT_PUBLIC_DIRECTUS_URL`, `DIRECTUS_ADMIN_TOKEN`, `TELEGRAM_BOT_TOKEN`, `NEXT_PUBLIC_BASE_PATH`, `SESSION_SECRET`, `INVITE_ADMIN_SECRET`, `NEXT_PUBLIC_APP_URL`) — заглушки, не реальные секреты.
- Никогда не коммить содержимое `.env*`, реальные токены, ключи. Если где-то в выводе тестов/логов встретился секрет — маскируй перед тем как класть в progress log.
- В конце каждой рабочей сессии: закоммить + запушить в `chordpro-viewer` (если тесты зелёные), обновить чеклист и Progress Log ниже.
- Если тесты/линт не проходят и причина не очевидна за разумное время — зафиксируй в Progress Log что именно сломано и на чём остановился, НЕ коммить сломанное состояние в основную историю (можно закоммить как WIP с пометкой, но не выдавать за готовый этап).
- Архитектурные развилки, которые требуют решения Игоря (не техническая деталь, а выбор с trade-off) — НЕ угадывать. Записать варианты в Progress Log под заголовком `## NEEDS DECISION` и остановиться на этой задаче, перейти к следующей независимой задаче.
- Никогда не выполнять `npm run deploy` и не трогать прод Directus (создание/изменение коллекций, прав, схемы) — это в списке решений, требующих Игоря явно (см. §7 спеки — сетлисты нужен новый junction/права в Directus).
- Не переписывать типографику аккордов (`tokenizeChord`, `chordSign*` в `songs.css`) без явной задачи это сделать — она уже прошла ручную проверку.
