## Решения, закрытые окончательно

1. **Идентификатор песни — integer `songs.id`.** Миграцию на `slug` не делать ни на одном
   этапе (обоснование — спека §7). Устаревшие комментарии про «id из имени файла» можно
   поправить текстом, поведение — нет.
2. **Настройки раскладки — свойство устройства**, один localStorage-ключ `songs:view-settings`.
   Тональность и пометки — свойство музыканта (спека §7), см. ниже.
3. **Типографику аккордов не трогать** без явной задачи: `tokenizeChord` в `ChordRenderer.tsx`
   и `chordSign*` в `songs.css` прошли ручную проверку на реальном корпусе (спека §3.4).
4. **Дефолт `mode` — `scroll`** на любом устройстве; авто-выбора по ширине нет.
   В `sheets`/`paged` авто-скрытие шапки отключено (смена высоты вьюпорта пересобирает листы).

## Персист пользовательских данных (сквозной вопрос M4/M5/M10)

Спека §7 требует, чтобы тональность, скорость автоскролла и штрихи ехали за музыкантом
между устройствами (Directus `song_user_state`). Но запись пользовательских данных обязана
идти через write-ahead outbox (офлайн-инварианты `CLAUDE.md`), а обобщение outbox — это M6,
которого ещё нет, и BFF по песням сейчас только GET.

**Рабочее допущение:** до M6 такие данные персистятся устройство-локально (localStorage,
скоуп «песня + настройка»), слой персиста прячется за одним модулем с узким API, чтобы
подмена хранилища на outbox+Directus в M6 была локальной правкой. Синхронизация между
устройствами до M6 не заявляется пользователю.

  установлен. Зависит от M6.

### Без требований в спеке — постановку собрать до реализации

Не изобретать требования. Дойдя до такого этапа — сформулировать вопросы и остановиться.

- **M2 — роли доступа. ✅ готово** (план `feature-setlists.md`, T1–T3). Итог: `AppRole` =
  `reader` / `musician` / `musician_editor` (`src/lib/app-roles.ts`), роль приходит из
  `GET /api/user/role`. Права: `musician` — CRUD сетлистов; `musician_editor` — то же
  **плюс** создание и редактирование песен (`canEditSongs`, ждёт M9). Реальный гейт — BFF
  (`requireSetlistWrite`), Directus-права — второй рубеж: приложение ходит админ-клиентом.
- **M6 — обобщение outbox.** `OutboxRecord` (`src/shared/offline/db.ts`) жёстко под прогресс
  чтения (`op: 'single'|'batch'`, `dayIds`, `count`). Форма обобщения — архитектурное решение.
  Тронет офлайн-контур ⇒ полный production-контур верификации обязателен.
- **M7 — сетлисты. ✅ готово** (план `feature-setlists.md`). Слайс `features/setlists`,
  BFF-роуты `/api/setlists*` под `requireSetlistWrite`, запись — online-only (осознанное
  исключение из offline-first), чтение — read-through + IDB. `song_user_state` пока не
  подключён — это M6.
- **M9 — редактирование песен.** BFF по песням только GET. Кто редактирует — решено:
  `musician_editor` (`canEditSongs` уже есть, пока не вызывается). Открыто: что именно
  редактируется и как разруливаются конфликты. Запись — через outbox (M6), не прямым POST.

## Правила работы (любой этап)

### Границы
- Только ветка `chordpro-viewer`. Не трогать `main`, `deploy/`, прод-конфиги, `.env*`.
- Никогда не выполнять `npm run deploy`. Прод-Directus (коллекции, поля, права, схема) —
  ручная работа Игоря.
- Держаться рамок этапа: попутные улучшения — текстом, а не коммитом.
- Проект на **Yarn 1**. `npm install` молча переписывает `yarn.lock` — не использовать.

### Секреты
- `.env.test` gitignored; в свежем клоне его нет. Нужен для тестов — создать с **фиктивными**
  значениями по `ENV_SETUP.md`. Не коммитить.
- Реальные секреты не печатать и не логировать; в выводе — маскировать (`sk-***`).

### Верификация (без этого этап не готов)
1. `yarn test` — всегда зелёный (baseline на 2026-07-25: **421 тест**).
2. `yarn lint` — на ветке унаследованный долг: **59 errors / 30 warnings**. Ноль недостижим и
   не требуется. Критерий: снять числа ДО работы, после правок они не выросли, в тронутых
   файлах ошибок нет.
3. `npx tsc --noEmit` — чисто.
4. Тронул offline/SW/кэширование/роутинг — дополнительно полный прод-контур:
   `yarn build` → просмотреть реальный `out/sw.js` → `yarn e2e:offline`. Dev-режим эти баги не ловит.
5. Playwright в чистом окружении: браузеры не ставятся через install зависимостей —
   `npx playwright install --with-deps chromium`. Не удалось прогнать — правка **не проверена**:
   зафиксировать `E2E НЕ ПРОГНАН: <причина>` и этап не закрывать.
6. При падении проверки чинить причину, а не тест.

### Когда останавливаться
- Архитектурная развилка с trade-off (а не техническая деталь) — не угадывать: варианты в
  `## NEEDS DECISION` детального плана этапа, перейти к следующей независимой задаче.
- Этап без раздела требований в спеке — требования не изобретать.
