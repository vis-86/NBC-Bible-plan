привязки к строке — и прототип показал, что она реально переживает и 18→26px, и
1→2 колонки (скриншоты в обсуждении 2026-07-29).

### Индустрия (forScore / OnSong / Newzik / Piascore)

- **Instant annotation** — стилус коснулся листа → режим включился; пауза → сохранился и
  вышел. Убирает два тапа на каждую пометку, а на репетиции их десятки.
- **Prevent finger drawing** — палец скроллит и зумит, рисует только перо. В браузере
  системного palm rejection нет вообще, и это **единственный доступный способ** отсечь
  ладонь: фильтр `pointerType === 'pen'`.
- **Слои аннотаций** (forScore: дирижёрские / личные, включаются независимо) — **вне v1**.
- **Цветовое кодирование** — маленькая фиксированная палитра (8 цветов), не color picker.
- Явное «Готово / Отменить», подтверждение на «Очистить всё».

### Web-специфика, которой нет в спеке

- `getCoalescedEvents()` — точки, склеенные браузером в одно `pointermove`. Без них быстрый
  штрих угловатый. **Список бывает пустым** — обязателен фолбэк на само событие
  (наступили прямо в прототипе: штрихи молча теряли все точки кроме первой).
- `pointerrawupdate` — ниже задержка, чем у `pointermove`; опционально.
- `e.pressure` даёт переменную толщину пера; у пальца и мыши это константа 0.5.
- `touch-action: none` на слое — иначе браузер съест жест как скролл.

## Модель данных

```ts
/** src/features/songs/types.ts */
export interface SongStroke {
  /** `arrow` — прямой отрезок с наконечником: ровно две точки (начало, остриё). */
  tool: 'pen' | 'highlighter' | 'arrow' | 'text';
  /** Якорь: индексы секции и строки в распарсенной песне (§6). */
  anchor: { section: number; line: number };
  /** px относительно bounding box строки-якоря. Для 'text' — одна точка. */
  points: Array<[x: number, y: number, pressure: number]>;
  color: string;
  width: number;
  /** Только для tool === 'text'. */
  text?: string;
  /** Только для tool === 'text': пометка на поле вдоль колонки (`writing-mode: vertical-rl`). */
  vertical?: boolean;
}

export interface SongAnnotations {
  strokes: SongStroke[];
  /** LWW-метка: побеждает запись с большим значением. */
  updatedAt: number;
}
```

**Осознанные ограничения (записать в спеку, не «чинить» по ходу):**

1. Штрихи **не масштабируются** вместе с текстом при смене `fontSize` — едут со строкой,
   но остаются прежнего размера (§6 это принимает).
2. Штрих, нарисованный на широком листе, при переходе в 2 колонки может вылезти за колонку
   (видно в прототипе). Митигация — клип слоя по bbox колонки, не пересчёт геометрии.
3. Индексы `section`/`line` ломаются, если песню отредактируют (M9). Принятый риск; при
   реализации M9 понадобится либо инвалидация заметок, либо якорь по хэшу строки.
4. Конфликт двух устройств — last-write-wins по `updatedAt`, без предупреждения. Тот же
   компромисс, что уже принят для сетлистов.

## Архитектура

### Контур доступа (безопасность — не пропустить)

BFF ходит в Directus **админ-токеном**, поэтому права Directus здесь второй рубеж.
`user_id` берётся **только из iron-session** (`directus_id`), никогда из тела запроса и
никогда из заголовка — иначе любой авторизованный читает и переписывает чужие заметки.
Это ровно тот класс дыры, что уже закрывали в `directus-proxy` (см. память проекта).

```
GET /api/songs/:id/state   → { strokes, updatedAt } | 404   (нужна сессия)
PUT /api/songs/:id/state   → upsert по (user_id из сессии, song)
```

Роль не проверяется: заметки — личные, их ведёт любой авторизованный, включая `reader`.

### Слой рисования

```
SongPage
└── SwipePager                       ← в режиме рисования ОТКЛЮЧЁН
    └── viewport (скролл)            ← в режиме рисования заморожен
        └── stage (transform: scale) ← зум живёт только здесь, не персистится (§6)
            ├── SongView             ← строки получают data-song-line-section/-index
            └── SongInkLayer         ← canvas + DOM-слой текстовых заметок
```

**Критично для режима `sheets`:** он рендерит N клонов всего потока, поэтому поиск
строки-якоря обязан быть **scoped внутри своего листа** (`root.querySelector`), а не по
документу — иначе `document.querySelector` вернёт строку первого листа и все штрихи
съедут на первую страницу.

### Персист

```
UI → songAnnotationsStore (узкий API)
      ├─ чтение: read-through (сеть с таймаутом + onLine===false fail fast) → IDB
      └─ запись: outbox (write-ahead) → replay при появлении сети → Directus
```

`OutboxRecord` расширяется дискриминированным union'ом:

```ts
type OutboxRecord =
  | { kind: 'progress'; op: 'single' | 'batch'; ... }       // существующее, поля не трогать
  | { kind: 'songAnnotations'; songId: number; payload: SongAnnotations; id: string; ts: number };
```

Записи без `kind` (созданные до этой правки и лежащие в IDB у пользователя прямо сейчас)
читаются как `'progress'` — иначе апдейт молча потеряет неотправленный прогресс.

**T1b. Уникальность `(user_id, song)` — через детерминированный `id`, а не индекс.**

Directus REST API **не умеет составные индексы**: `is_unique` существует только на одном
поле, эндпоинта для индексов нет. Прямой SQL потребовал бы доступа к БД на сервере —
лишняя ручная операция в проекте, который поддерживают волонтёры.

Вместо этого `id` записи вычисляется как **UUIDv5 от `"{user_id}:{song}"`** в фиксированном
namespace-константе. Дубликат тогда невозможен по построению — его ловит сам первичный ключ,
без единой правки схемы.

Проверено на проде живыми запросами (тестовая строка под `claude-offline-test`, удалена):

| Проверка | Результат |
| :--- | :--- |
| `POST` с явным `id` | 200, запись создана |
| Повторный `POST` с тем же `id` | 400 `RECORD_NOT_UNIQUE` |
| `PATCH` по тому же `id` | 200, путь обновления работает |
| `POST` без `user_id`/`song` | 400 `FAILED_VALIDATION` (NOT NULL держит) |
| Уборка | строка удалена, в коллекции снова 0 записей |

Namespace-UUID — **одна экспортируемая константа** рядом с функцией вычисления id,
импортируемая и писателем, и читателем. Смена namespace осиротит все существующие записи.

**Стрелка** — главный рабочий инструмент музыканта после пера: «повтор отсюда», «переход
на этот куплет», указание на аккорд. Ровно две точки: начало фиксируется на `pointerdown`,
остриё тянется за пальцем (последующие точки **заменяют** вторую, а не добавляются).

- Геометрия — **один замкнутый полигон** (древко + наконечник вместе). «Прямоугольник плюс
  треугольник» двумя субпутями даёт ту же дыру в месте стыка, что и наивный штрих.
- Наконечник ограничен половиной длины стрелки, иначе короткая стрелка вырождается в клин.
- Тап без протяжки не должен создавать запись — иначе на листе копятся невидимые штрихи
  из одной точки.
- Ластик обязан считать расстояние **до отрезка, а не до точек**: у стрелки точек всего
  две, и середина древка иначе не стирается вовсе. Заодно это чинит стирание длинных
  прямых участков обычного штриха.

**Текстовая заметка живёт в DOM, а не в canvas** — именно потому, что её надо выделять,
двигать и поворачивать:

- **Перетаскивание.** Тап без движения выделяет заметку, движение — тащит. На отпускании
  заметка **перепривязывается к ближайшей строке**: утащенная к другому куплету, она иначе
  продолжит ездить за исходной строкой при смене шрифта.
- **Вертикальная ориентация** (`writing-mode: vertical-rl`) — поле `vertical: boolean` в
  модели. Пометка на правом поле вдоль колонки: бумажная классика, на узком телефоне часто
  единственное место, где заметка помещается.
- У выделенной заметки — компактная панель над ней: **повернуть / изменить текст / удалить**
  (разрушающее действие последним). Правка — именно кнопкой, а не двойным тапом: тап и
  перетаскивание уже заняты, третий жест поверх них никто не найдёт. Поле ввода встаёт
  ровно на место заметки, предзаполненное текущим текстом; пустой текст = удаление, иначе
  на листе останется пустая рамка.
- Перетаскивание и выделение работают **только когда активен текстовый инструмент**, иначе
  заметки перехватывают штрихи пера и попадания ластика.
- Перетаскивание, поворот и правка текста кладутся в тот же undo-стек, что и штрихи.

Три ловушки, на которых прототип упал:

1. Слой заметок перерисовывается покадрово — обработчики жеста, повешенные **на сам
   элемент**, умирают вместе с ним после первого же движения. Слушать надо `window`.
2. `setPointerCapture` бросает исключение, если захват невозможен, и убивает весь жест
   вместе с навешиванием обработчиков. Захват — не обязательное условие: обернуть в
   `try/catch` и продолжать.
3. **Undo для правки существующего объекта требует копии самого объекта, а не только
   массива.** `strokes.slice()` копирует массив, но объекты в нём те же — поворот,
   перетаскивание и смена текста меняют заодно и «старое» состояние в стеке, и undo
   визуально ничего не откатывает. Для штрихов это не всплывало (они только добавляются
   и удаляются целиком) и вылезло ровно на редактируемых заметках.
   Тест: поворот → undo возвращает горизонтальную; перетаскивание → undo возвращает
   исходную позицию; правка текста → undo возвращает прежний текст.

**Ещё три обязательные детали ввода** (все три сломались в прототипе):
1. Поле ввода лежит внутри слоя рисования, поэтому обработчик слоя обязан **игнорировать
   события с самого поля** — иначе тап по нему открывает второе поле, первое теряет фокус
   и отбрасывается пустым: заметку невозможно набрать в принципе.
2. Коммит **не вешать на `blur`** как на единственный путь: если фокус не встал (iOS
   отдаёт его не всегда), набранный текст пропадает молча. Нужен явный `commit()`,
   вызываемый и следующим тапом, и кнопкой «Готово», с защитой от двойного вызова.
3. Пока набирают текст, таймер instant annotation должен сбрасываться, иначе режим
   закроется прямо посреди ввода.
*Depends on: T7, T8.*

**T10. ✅ Навигация по листу внутри режима рисования, зум, отключение конкурирующих жестов.**

**Правка спеки.** §6 требует «лист замораживается, скролл выключен». Для длинной песни это
тупик: до второго куплета в режиме пометок не добраться (нашли на прототипе 2026-07-29).
Заморозка нужна лишь потому, что палец рисует, — значит и снимать её надо там, где палец
не рисует. Реализуемое поведение:

| Режим | Палец | Перо | Нативный скролл |
| :--- | :--- | :--- | :--- |
| «Только стилус» **выкл** | 1 палец рисует, **2 пальца прокручивают и зумят** | рисует | выключен, прокрутка через жест |
| «Только стилус» **вкл** | прокручивает и зумит штатно | рисует | **включён** (`touch-action: pan-y`) |

- Второй указатель **отменяет уже начатый штрих** — иначе каждый двухпальцевый жест
  оставляет на листе случайную закорючку от первого пальца.
- Десктоп: колесо прокручивает замороженный лист, `Ctrl`/`⌘` + колесо (пинч на трекпаде) зумит.
- Зум — `transform` на обёртке слоя, при выходе сбрасывается в 1 (§6: не персистится).
- **`transform: scale()` не меняет layout-размер**, поэтому диапазон прокрутки не растёт и
  правый с нижним краем увеличенного листа недостижимы. Обёртке нужно явно проставлять
  `width`/`height` = натуральный размер × масштаб. Тест: при зуме ×2 `scrollHeight`
  и `scrollWidth` контейнера растут примерно вдвое.
- Текущий масштаб виден в шапке режима и сбрасывается тапом по нему — иначе из зума
  выбираются только выходом из режима.
- **`SwipePager` обязан быть отключён в режиме рисования** — иначе горизонтальный штрих
  пролистывает песню сета. Первый штрих ставит автоскролл на паузу.
- Подсказка при входе в режим называет активный жест — двухпальцевую прокрутку иначе
  никто не найдёт.

Тесты: два указателя прокручивают контейнер и не оставляют штрих; включение «только
стилуса» снимает заморозку; включение режима снимает обработчики пейджера; выход
возвращает зум в 1.
*Depends on: T9.*

**T11. ✅ Тумблеры «только стилус» и «instant annotation».**
Хранятся как настройки устройства (`useSongViewSettings`, блок «Отображение»), не на песню.
«Только стилус»: рисует лишь `pointerType === 'pen'`, палец скроллит и зумит даже внутри
режима. «Instant annotation»: касание пером вне режима включает режим и **не теряет первое
касание**; пауза 4 с → сохранение и выход.
Тесты: с выключенным «только стилус» палец рисует; с включённым — нет; instant не
срабатывает от пальца.
*Depends on: T10.*
