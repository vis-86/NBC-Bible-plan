# 502 на всём /api: транзитивный импорт `songsServer → ../lib/searchText` не попал в bff-образ

**Date:** 2026-07-30 01:20
**Files:** deploy/Dockerfile, server/src/runtime-closure.test.ts
**Severity:** critical

## Problem

На проде «перестало работать логин»: форма показывала «Ошибка входа».
Фактически лежал весь API — nginx отдавал 502 на `/app/api/*`, статика (`/app/login`)
при этом работала (200), из-за чего симптом выглядел как баг логина, а не как падение BFF.

`docker compose ps` — `nbc-bible-bff-1  Restarting (1)`, в логах crash-loop:

```
Error: Cannot find module '../lib/searchText'
Require stack:
- /app/src/features/songs/services/songsServer.ts
- /app/server/src/routes/songs.ts
```

## Root Cause

Уже известный класс бага (`bff-runtime-closure`), но новая его разновидность —
**транзитивный** импорт.

`deploy/Dockerfile` (stage `bff`) копирует не весь `src/`, а whitelist каталогов.
Коммит `abcd`-серии по поиску песен (`abaa5ec feat(songs): extract searchable plain
text from chordpro`) добавил в `src/features/songs/services/songsServer.ts` импорт
`../lib/searchText` → `src/features/songs/lib/*`. Этот каталог в whitelist не входил:
копировался только `src/features/songs/services`.

Гейт `server/src/runtime-closure.test.ts`, который существует ровно для этого инварианта,
проблему не поймал: он сканировал импорты **только файлов `server/src`** — один шаг.
Импорт появился на втором шаге (`server/src/routes/songs.ts` → скопированный
`songsServer.ts` → `../lib/searchText`), то есть в слепой зоне гейта.

Локально и в тестах невидимо: там доступно всё дерево репозитория.

## Solution

1. `deploy/Dockerfile`: добавлены `COPY src/features/songs/lib` и
   `COPY src/features/songs/types.ts`. Копируется каталог целиком, а не два файла —
   дальнейшие импорты внутри songs/lib не потребуют правки инфраструктуры
   (лишние клиентские модули в образе не исполняются, вес ~100 КБ).
2. `server/src/runtime-closure.test.ts`: обход стал **транзитивным** — BFS по графу
   импортов, заходящий внутрь разрешённых `src/`-файлов, с резолвом `@/`-алиаса,
   расширений и `index.ts`. `import type` осознанно не отделяется (tsx их стирает,
   но требовать COPY для всего проще и не даёт ошибиться на смешанных формах).
   COPY-пути нормализуются отсечением `.ts`/`.tsx`, чтобы файловые COPY-строки
   сопоставлялись с импортами без расширения.
   Проверено обратным экспериментом: без новой COPY-строки гейт краснеет на
   `searchText` и `chordProUtils` (было 22 кейса → стало 33).
3. Прод: `deploy/` исключён из rsync, поэтому Dockerfile доставлен `scp` вручную,
   затем `docker compose up -d --build bff`. Пересобирался только bff.

Проверка после восстановления: `/api/health` → 204, `POST /api/auth/login` с
неверными кредами → 401 `Invalid user credentials.` (значит цепочка BFF→Directus
жива целиком), `/api/songs` → 200.

## Prevention

- Гейт runtime-замыкания обязан быть **транзитивным**: whitelist-COPY ломается не
  только импортом из `server/src`, но и импортом внутри уже скопированного `src/`-файла.
  Любой «сканер одного уровня» над графом зависимостей — ложное чувство защиты.
- Симптом «сломался логин» на проде: сначала `curl /app/api/health`. 502 при живой
  статике = BFF не поднялся, и искать надо в `docker compose logs bff`, а не в auth-коде.
  Статика и API — разные контейнеры, падение API не трогает страницы.
- Smoke после деплоя должен дёргать API, а не только страницу: `GET /app/login` → 200
  проходит при полностью мёртвом BFF.
- Перед деплоем фичи, добавившей импорты в `src/features/*/services`, гонять
  `npx vitest run server/src/runtime-closure.test.ts` — он дешёвый и покрывает
  ровно этот класс отказа.
