# Создание аккаунта падало с 500: Directus отклоняет email `{login}@local`

**Date:** 2026-06-30 23:45
**Files:** src/lib/directus-user.ts, src/lib/directus-user.test.ts
**Severity:** high

## Problem

`POST /api/auth/register` (и `POST /api/auth/activate`) на проде возвращал
500 Internal Server Error при создании аккаунта. В логах контейнера:

```
[register] error: {
  message: 'Validation failed for field "email". Value has to be a valid email address.',
  ...
  url: 'http://directus:8055/users'
}
```

403/400-проверки (код церкви, zod) проходили — падало уже на `createLocalUser`.

## Root Cause

Псевдонимная модель создаёт пользователя с синтетическим email
`{login}@local` (`LOCAL_EMAIL_DOMAIN = 'local'`). Directus v11 валидирует
формат email и **отклоняет single-label домены без точки** (`@local`,
`@local.invalid`, `@local.local` — все 400). Требуется домен с реальным TLD.

Баг латентный: `createLocalUser` используется и invite-активацией, и
self-registration — но всплыл только сейчас, при первой реальной регистрации
на пересобранном проде (старый сервер умер без бэкапа; на новом Directus v11
строго валидирует email, и `@local`-аккаунтов ещё не было).

Подтверждено пробами через admin API: `@example.com`, `@local.baptistnn.ru`,
`@nbc.app` принимаются; `@local`, `@local.invalid`, `@local.local` — отклоняются.

## Solution

`LOCAL_EMAIL_DOMAIN`: `'local'` → `'local.baptistnn.ru'` — поддомен своего
домена (реальный TLD `.ru` проходит валидацию Directus; без MR-записи →
формат валиден, почта не доставляется, ПД не появляются). Все потребители
(`login`, `telegram/link`, `createLocalUser`) идут через `loginToEmail` —
одной правки константы достаточно. Миграция не нужна: `@local`-аккаунтов на
проде не было (проверено фильтром по email).

## Prevention

- Синтетические/фейковые email ВСЕГДА с реальным TLD (домен с точкой). Зарезервированные `.local`/`.invalid`/`.test` НЕ проходят валидаторы, проверяющие TLD.
- При интеграции с внешним сервисом (Directus) — проверять его валидацию полей реальной пробой через API, не полагаться на «формат выглядит ок».
- Smoke-тест после деплоя должен покрывать **полный** путь (реальное создание аккаунта + cleanup), а не только 200 на GET /login — тогда 500 на создании ловится сразу.
- Регрессия закрыта тестом: `loginToEmail('x')` домен содержит точку и не равен `local`.
