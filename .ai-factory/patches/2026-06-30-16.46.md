# Invite link immediately redirects to /login (public page caught by global 401 handler)

**Date:** 2026-06-30 16:46
**Files:** src/shared/services/api/client.ts, src/shared/services/api/endpoints.ts, src/shared/services/api/client.test.ts
**Severity:** high

## Problem

Opening an invite link (`/activate?token=…&mode=activate`) immediately redirected to
`/login`, so no one could activate an account or reset a password. The activation form
never rendered.

## Root Cause

`ThemeProvider` is mounted by the **root layout**, so it runs on *every* page — including
public ones (`/activate`, `/login`). On mount it bootstraps the theme via
`appSettingsApi.getSettings()` → `GET /api/user/app-settings`, which is a **session-protected**
route. On a public page there is no session yet → the route returns **401**.

The shared `ApiClient.request()` has a *global* 401 hook: on any 401 it calls
`__onSessionExpired()` (registered by `AuthProvider`), which does `router.push('/login')`.
That hook is meant for *authenticated areas* where a session genuinely expired — but it fired
for the theme bootstrap on a public page, bouncing the user to `/login` before the activate
form could mount. `ThemeProvider`'s own `.catch()` was irrelevant: the redirect happens inside
`request()` before the promise rejects.

The middleware was a red herring — it only guards `/dashboard`, not `/activate`.

## Solution

Gave the already-existing-but-unused `skipAuth` request option real meaning: a 401 on a
`skipAuth` request no longer triggers the global session-expired redirect (it still throws
`ApiClientError(401)` so callers can handle it). The theme bootstrap
(`appSettingsApi.getSettings`) now passes `skipAuth: true`, since it's a best-effort call that
already falls back to `'system'`. Authenticated data calls (plan/progress/etc.) keep the
redirect behavior, so genuine session expiry still bounces to login.

## Prevention

- A "fire on every page" call (providers in the root layout) must never hit a
  session-protected endpoint without opting out of global auth side-effects. Mark such calls
  `skipAuth`.
- Global 401→redirect handlers are dangerous on public routes. When adding one, scope it: either
  per-request opt-out (this fix) or gate it on the current route being protected.
- Test both branches of the 401 handler (with/without `skipAuth`) — added in `client.test.ts`.
