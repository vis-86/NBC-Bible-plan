# Автоскролл перекрывал шторку транспонирования + скорость должна быть per-song, не глобальной

**Date:** 2026-07-26 01:14
**Files:** src/features/songs/components/SongKeyPicker.tsx, src/app/dashboard/song/page.tsx, src/features/songs/lib/autoScrollSpeedStore.ts (new), src/features/songs/lib/autoScrollSpeedStore.test.ts (new), src/features/songs/hooks/useSongViewSettings.ts, src/features/songs/hooks/useSongViewSettings.test.ts, src/features/songs/hooks/useAutoScroll.ts, e2e/layout/song-autoscroll.spec.ts
**Severity:** medium

## Problem

Two regressions found in code review after the M5 autoscroll feature shipped:
1. The autoscroll control (`SongAutoScroll`, speed buttons + play/pause FAB) visually overlapped the "Transposition" bottom sheet (`SongKeyPicker`) when open in `scroll` mode.
2. Autoscroll speed was stored as ONE global setting for all songs (`autoScrollStep` field folded into `useSongViewSettings`), when it should be per-song (as in the original M5 design).

## Root Cause

1. `SongKeyPicker` owned its `isOpen` state entirely internally — the page component had no way to know the transposition sheet was open, so it could only gate `SongAutoScroll` on `isViewSettingsOpen` (a previous, similar fix for the view-settings sheet), missing this second sheet.
2. A prior edit folded `autoScrollStep` into `useSongViewSettings` (one JSON blob under `songs:view-settings`) instead of keeping the original per-song `autoScrollSpeedStore.ts` module (deleted at some point), losing the "each song remembers its own speed, falling back to the last globally chosen speed" behavior.

## Solution

- Added an optional `onOpenChange` prop to `SongKeyPicker`, invoked on every `isOpen` transition (open/close/reset), additive so no other call sites break.
- Page now tracks `isKeyPickerOpen` and extends the `SongAutoScroll` render gate to `!isViewSettingsOpen && !isKeyPickerOpen` — the same "hide on any open bottom sheet" pattern already used for view settings, rather than chasing an exact z-index/stacking-context root cause.
- Restored `autoScrollSpeedStore.ts`, mirroring `personalKeyStore.ts`'s pattern: a per-song map (`songs:autoscroll-speed`) plus a global "last selected" fallback (`songs:autoscroll-last`), single listener set for `useSyncExternalStore`, graceful localStorage fallback with warn-once.
- Removed `autoScrollStep` from `useSongViewSettings`/`DEFAULT_SONG_VIEW_SETTINGS`/`sanitize()`.
- `useAutoScroll` now reads/writes speed itself via `useSyncExternalStore(subscribeAutoScrollSpeed, () => readSpeedStep(songId), ...)` and exposes `step`/`setStep` in its result, instead of receiving `step` as a prop.

## Prevention

- When a bottom sheet's open state needs to affect page-level layout/overlays, lift that state via an `onOpenChange` callback at the moment the component is introduced — don't wait for a second sheet to expose the gap.
- Per-entity settings (per-song, per-user) should never be folded into a single global settings blob "for convenience" — check whether a value is supposed to vary by entity ID before adding it to a flat settings object plan `personalKeyStore.ts`.
- When restoring code that was previously reverted/deleted, grep for the original module name first (`autoScrollSpeedStore`) — the intended design was already recoverable from an earlier plan (`feature-song-autoscroll.md`).
