# Свайп-пейджер: хинт и кнопки скорости уезжали из-за CSS-свойства `translate` (Tailwind v4)

**Date:** 2026-07-27 23:30
**Files:** src/shared/components/pager/PagerHint.tsx, src/features/songs/components/SongAutoScroll.tsx (+ тесты)
**Severity:** high

## Problem

После доработок свайпа (коммиты `01fe604`, `607c44b`) на устройстве:

- подсказка «N из M» рендерилась не по центру области чтения, а смещённой
  влево-вверх ровно на половину своего размера (на телефоне — прижата к левому краю);
- кнопки скорости автоскролла и play/pause-FAB уезжали за правый край экрана
  (виден только срез иконки), вместо правого края по центру высоты.

## Root Cause

Tailwind v4 генерирует translate-утилиты через **CSS-свойство `translate`**, а не
через `transform`:

```css
.-translate-x-1\/2{--tw-translate-x:calc(calc(1/2*100%)*-1);translate:var(--tw-translate-x)var(--tw-translate-y)}
```

Отсюда два независимых следствия, оба сработали:

1. `PagerHint` центрировался классами `-translate-x-1/2 -translate-y-1/2` И задавал
   inline `transform: translate(-50%,-50%) scale(...)`. В v3 inline-transform просто
   перебил бы утилиты; в v4 это **разные свойства**, они складываются → двойной сдвиг
   на половину бокса.
2. `SongToolStack` анимирует скрытие классами `translate-y-24`/`translate-y-0`, то есть
   у него всегда есть ненулевое свойство `translate`. Любое из
   `transform/translate/rotate/scale` создаёт **containing block для `position: fixed`**
   потомков. `SongAutoScroll` рендерил себя как `fixed inset-0` оверлей вьюпорта (в
   комментарии прямо стояло «transform/filter, которых тут нет») — и раскладывался
   внутри 48-пиксельного бокса стека: `p-4` + `justify-end` выталкивали FAB за экран,
   а `absolute right-3 top-1/2` панель скорости — тем более.

Общий корень: при переходе на Tailwind v4 «transform-предположения» перестали быть
верными, а SongToolStack (новый компонент) добавил `translate` над старым `fixed`-оверлеем.

## Solution

- `PagerHint`: inline `transform` убран совсем, центрирование остаётся за
  translate-утилитами, масштаб задаётся отдельным CSS-свойством `scale`
  (`transition-[opacity,scale]`).
- `SongAutoScroll`: полноэкранного `fixed inset-0` оверлея больше нет. Play/pause —
  обычный элемент потока, позицию задаёт `SongToolStack` (обёртка `display: contents`,
  чтобы FAB остался flex-элементом стека). Панель скорости — оверлей уровня вьюпорта,
  поэтому уходит `createPortal` в `document.body` и там честно `fixed`. Гидратация не
  ломается: при первом рендере автоскролл всегда на паузе, панели в разметке нет.
- Тесты-регрессии: `PagerHint` не имеет inline `transform`; панель скорости лежит в
  `body`, а не внутри `[data-song-tool-stack]`.

## Prevention

- В Tailwind v4 **не смешивать** translate/scale/rotate-утилиты с inline `style.transform`
  на одном узле: это разные CSS-свойства, они складываются. Либо всё в утилитах, либо всё
  в inline — и тогда через отдельные свойства `translate`/`scale`.
- Перед тем как класть `position: fixed` внутрь компонента-контейнера, проверить всю цепочку
  предков на `transform | translate | rotate | scale | filter | backdrop-filter | will-change |
  contain` — любое из них делает `fixed` относительным. Комментарий «трансформов тут нет»
  протухает ровно тогда, когда над компонентом появляется анимированная обёртка.
  Оверлеи уровня вьюпорта, живущие внутри чужого контейнера, надёжнее рендерить порталом.
- Ревью-чек: новый компонент-обёртка с анимацией скрытия (`translate-y-*`) — сразу смотреть,
  нет ли среди потомков `fixed`.
