# Visible jump on snap in DayNavigationBar carousel

**Date:** 2026-05-08 16:39
**Files:** src/features/plan/components/DayNavigationBar.tsx
**Severity:** medium

## Problem

Пользователь видит «небольшой прыжок» в карусели `DayNavigationBar` в момент snap на новый день. Логи в консоли:

```
center → 114
center → 115
scrollend → snap to 115
[DashboardPage] view from URL param ... (4-5 раз подряд)
snap pulse for 115
```

Visual artefact возникает именно после `snap to 115` и серии re-render'ов `DashboardPage`, не во время скролла.

## Root Cause

Совокупность трёх факторов:

1. **Cascade re-renders на snap.** `onSnapToDay → setSelectedDayId → window.history.replaceState({day: N})`. В Next.js 16 `useSearchParams()` отлавливает `replaceState` и trigger'ит `DashboardPage` ре-рендер 4-5 раз подряд (множественные batches React 19 + Suspense). Все потомки (`PlanView` → `DayNavigationBar` → 365 × `CubeMotion`) ре-рендерятся.

2. **`CubeMotion` без React.memo + нестабильный `handleCubeClick`.** На каждый ре-рендер пересоздавался `useCallback`-handler с зависимостями `[centerDayId, selectedDayId, onSelectDay, scrollToDay]`. `centerDayId` меняется на каждом scroll-frame — handler reference дрейфит — `React.memo` (если бы был) сломан. По факту `memo` не было — все 365 кубиков ре-рендерились на каждое движение пальца, не только при snap.

3. **Двухуровневый `useTransform`** (`scrollX → distance → scale`). Промежуточный motion-value `distance` пере-подписывался на каждый rebuild компонента; в момент cascade re-render первый кадр после teardown давал scale=default(1.0) для всех кубиков → визуальный «прыжок».

4. **Pulse animation `scale: [1.18, 1.0]` с overshoot easing** `[0.34, 1.56, 0.64, 1]` — амплитуда 18% + overshoot воспринимались как «двойной отскок», что усиливало эффект прыжка.

## Solution

1. **`React.memo(CubeMotion, comparator)`** — кастомный компаратор сравнивает все 9 props по reference/value. Кубики ре-рендерятся только при реальном изменении статуса/выбора/индекса, не на каждый scroll-tick.

2. **Stable `handleCubeClick` через ref-pattern.** Перенёс `centerDayId/selectedDayId/onSelectDay/scrollToDay` в refs (обновляются в `useEffect`), сам `useCallback` теперь с пустыми deps `[]`. Handler reference никогда не меняется → `memo` работает.

3. **Один `useTransform` вместо двух.** `scrollX → scale` напрямую через manual piecewise-linear interpolation внутри transform-функции. Убран промежуточный `distance` motion-value — меньше re-subscription overhead, меньше шансов на «stale frame» при teardown.

4. **Pulse → scale [1.08, 1.0] + ease-out** `[0.16, 1, 0.3, 1]` (без overshoot). Амплитуда 8% вместо 18% + один rest-stop вместо bounce — субъективно ощущение «защёлкивания», а не прыжка.

## Prevention

- **Списки из >50 элементов в карусели/listbox с motion-values:** ВСЕГДА оборачивать item-компоненты в `React.memo` с явным comparator. `useTransform` per-item без memo = O(N) re-subscriptions per parent render.
- **Click/event-handlers, прокидываемые в memo'нутые children:** стабилизировать через ref-pattern (refs обновляются в useEffect, useCallback с пустыми deps). Альтернатива: useEvent (не стабилен в React 19), либо external state-store.
- **iOS-picker pulse animations:** избегать overshoot easing (`[a, b > 1, c, d]`) для частых событий — он ощущается как «прыжок», а не как snap. Использовать ease-out с амплитудой ≤10%.
- **Code review checklist для каруселей:**
  - Item-компонент мемоизирован?
  - Handlers стабильны (не пересоздаются на каждый scroll-tick)?
  - `useTransform` chain один уровень или два?
  - Pulse/snap animations ≤10% амплитуда без overshoot?
