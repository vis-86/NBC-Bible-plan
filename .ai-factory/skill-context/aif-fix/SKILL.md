## Rules

### Static export: check deployed bundle freshness before blaming sources
**Source**: 2026-07-10-21.17.md
**Rule**: Production = static `out/` + Serwist SW. For any "works locally, broken on prod" symptom, FIRST verify the deployed `out/` build timestamp vs the feature commit and whether the SW serves a stale precached bundle. Only then look at the sources — rebuilding/redeploying and busting the SW cache is often the whole fix.

### Verify the diagnosis against real production behavior
**Source**: 2026-07-09-01.27.md
**Rule**: Do not build a diagnosis on local uncommitted WIP code — the reported bug may exist independently in production (the WIP was a red herring for the nav-overlap bug). For flaky UI bugs without reproduction steps, ask for a screenshot/video before hypothesizing — a single prod screenshot exposed the real root cause.

### Offline bugs have two modes — test both reject and hang
**Source**: 2026-07-05-08.55.md, 2026-07-10-14.58.md
**Rule**: Airplane mode / DevTools offline rejects fetch instantly; real offline (dead cell, captive portal) HANGS it. Code written for one mode fails in the other (instant fallbacks vs eternal spinners). Every read-through/network-first fix needs test cases: "fetcher rejects + record in IDB", "fetcher never resolves (`new Promise(() => {})`) + record in cache", and "fetcher hangs + cache empty + `onLine === false` → must FAIL, not hang".

### Comments describing other modules' behavior: verify with grep
**Source**: 2026-07-04-21.58.md
**Rule**: A comment promising behavior elsewhere ("name will be refreshed on next session read") may describe code that was never written. Before relying on such a claim during diagnosis, grep for the actual implementation.

### Cache warm-up fixes don't heal existing installs
**Source**: 2026-07-10-16.46.md
**Rule**: Manifest-based guards (`ensureOfflineData` skips a download when the manifest entry exists) make backfill impossible: users who downloaded before the fix keep an empty cache until an online visit or data reset. State this limitation explicitly in the fix and consider a migration/backfill path.

### Vitest mechanics for module singletons and fake timers
**Source**: 2026-07-10-16.35.md
**Rule**: Module-level state leaks between tests of the same file (vitest isolates per file, not per test). When introducing a module singleton, export `reset*ForTests()` and call it in `beforeEach` of ALL test files whose subjects read it. Attach `.rejects` expectations BEFORE `advanceTimersByTimeAsync` — otherwise the rejection surfaces unhandled while the test stays green.
