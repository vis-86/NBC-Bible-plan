## Rules

### SW/offline verification chain: production build is mandatory
**Source**: 2026-07-03-18.06.md, 2026-07-03-11.27.md, 2026-07-03-16.03.md
**Rule**: Any service-worker or offline change is verified as: unit tests → `next build` (static export) → inspect the actually generated `sw.js` → drive a real offline navigation against the production build. `next dev`, Turbopack, and vitest all skip minification/bundling and never catch the "breaks only when built" class (minified free-variable references, RSC reload loops). Simulated-offline behavior in dev mode is unreliable (HMR websocket, unhashed chunks).

### A green setOffline test is not proof of working offline
**Source**: 2026-07-10-14.58.md
**Rule**: Playwright `setOffline(true)` rejects fetches instantly, triggering Next's MPA fallback that masks SW cache misses; real offline hangs instead. An offline test must assert that the network was NOT needed (e.g. MPA-fallback marker on `window` that survives SPA navigation but dies on reload, absence of `Failed to fetch RSC payload` console errors), not merely that content rendered. `page.route` cannot intercept requests that went through a service worker (playwright#1090); a cheap reliable check is a direct `fetch()` from an offline page for the exact URL Next would request.

### Check SSR output with curl for browser-global-dependent components
**Source**: 2026-07-03-11.27.md
**Rule**: In the Next.js Node runtime, `navigator` exists as a stub without `.onLine` — initial `useState` computed from browser globals silently yields wrong values instead of throwing. Verify SSR output directly with `curl` (grep for the component's data attribute), not just the hydrated DOM.

### Post-deploy smoke test covers the full critical path
**Source**: 2026-06-30-23.45.md
**Rule**: A 200 on GET /login is not a smoke test. Cover the full path — real account creation via invite + cleanup — so a 500 on user creation (e.g. Directus email validation) is caught immediately. The prod test account `claude-offline-test` exists for e2e/offline checks; preserve it.

### Visual verification hygiene
**Source**: 2026-07-07-23.51.md, 2026-07-03-11.27.md
**Rule**: Screenshots on dev builds bake in the Next.js dev-tools indicator: inject `nextjs-portal{display:none!important}` via `evaluate_script` immediately before EACH `take_screenshot` (the `initScript` param of `navigate_page` is unreliable across client-side transitions), or shoot the production build. DevTools "Offline" preset does not flip `navigator.onLine` — test `online`/`offline` event-driven UI by dispatching `window.dispatchEvent(new Event('offline'))` manually.
