## Rules

### Offline-touching plans must budget for both offline modes and the app-shell layer
**Source**: 2026-07-05-08.55.md, 2026-07-10-16.46.md, 2026-07-04-10.20.md, 2026-07-03-23.46.md
**Rule**: When a plan touches offline-readable resources or routing, include explicit tasks for: (a) timeout + `onLine===false` fail-fast on every new network-first path; (b) warming every read-through key in the download flow (writer/reader symmetry); (c) adding new `router.push` destinations to `APP_SHELL_ROUTES` and keeping client-readable params in search strings, not dynamic segments; (d) test tasks covering BOTH offline modes — instant fetch rejection AND a never-resolving fetch. Also budget the product of sequential timeouts (N screens × T), not the sum.

### Enumerate all consumers before adding state/policy to a shared primitive
**Source**: 2026-07-10-16.35.md
**Rule**: Before planning to embed domain behavior (network circuit breaker, retries) into a generic helper (`raceWithTimeout`, `withTimeout`), grep its imports and list EVERY consumer — one non-network consumer (`indexedDB.open`) turns the optimization into an outage of the very fallback layer. If a breaker can cut the path to its own fallback, it's an outage, not a breaker; plan a regression test for "open circuit does not affect the generic primitive".

### Self-registration is a feature decision, not a fix
**Source**: 2026-06-30-18.33.md
**Rule**: Accounts are created ONLY via invite (FZ-152, no email/PII); the register route was deliberately removed. Any plan reintroducing self-registration conflicts with that decision and requires the owner's explicit consent — never slip it in as a side task. (Note: prod currently runs a tri-state registration mode — check the server compose files as source of truth before planning auth changes.)
