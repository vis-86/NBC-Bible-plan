## Rules

### Network-first must have a timeout and fail fast when offline
**Source**: 2026-07-05-08.55.md, 2026-07-10-16.35.md, 2026-07-10-16.54.md
**Rule**: Real offline (dead cell, Wi-Fi without uplink) HANGS requests, it does not reject them. Every network-first path (fetch, SW navigation, read-through) MUST race against a timeout. Fallback pattern: cache exists → serve cache; cache empty AND `navigator.onLine === false` → fail with an error (never wait — the wait is infinite by construction); cache empty AND possibly-slow network → keep waiting. Trust `navigator.onLine` only when it is `false` (`true` means nothing — lie-fi). Sequential network-first screens multiply timeouts: N screens × T timeout = cold offline start cost; compute the product, not the sum. "Wait longer" is not error handling: for any `return promise` in a catch branch, answer "under what conditions does this promise never resolve?".

### Cache keys live in one exported constant shared by writer and reader
**Source**: 2026-07-10-16.46.md, 2026-07-10-14.58.md, 2026-07-10-21.17.md
**Rule**: A cache/storage key literal appearing in two places is a bug waiting to happen (`useSongs` vs `downloadSongs` diverged exactly this way). Any IDB/localStorage/precache key MUST be an exported constant imported by both the writer and the reader. For every `cache.match(x)` ask: "under which exact key was this written during install?" — any cache-busting query param (`_rsc`, `?v=`) makes an exact match impossible; strip or `ignoreSearch` deliberately.

### Download/warm-up must cover every key the screens read
**Source**: 2026-07-10-16.46.md, 2026-07-03-23.46.md
**Rule**: If a feature reads via `readThrough(key)`, its download/warm-up function MUST warm that same key (asserted in tests with the same call production uses, e.g. `getApiCache(KEY)` — not "data is somewhere in IDB"). When adding a read-through to a screen, verify warm-up covers ALL its logical keys. Note: manifest-based guards (`ensureOfflineData` skips when manifest entry exists) make backfill impossible for existing installs — account for that when changing warm-up.

### Serialized-to-string functions: pure args-only, verified on the minified production build
**Source**: 2026-07-03-18.06.md, 2026-07-03-11.27.md
**Rule**: Functions embedded via `.toString()` into generated scripts (`src/sw/sw-source.ts` → `sw.js`) MUST NOT reference anything outside their arguments — minification renames free variables and produces `ReferenceError` only in the production bundle. Extract every fetch/cache strategy branch into its own named, exported, unit-testable function (side effects like a forgotten `cache.put()` hide outside the routing decision). Checklist for touching `sw-source.ts`: unit tests → production build → inspect the real generated `sw.js` → drive a real offline navigation against that build.

### SW fetch handlers branch on request.mode; app-shell routes are explicit
**Source**: 2026-07-03-16.03.md, 2026-07-04-10.20.md, 2026-07-10-14.58.md
**Rule**: Always check `request.mode` (`navigate` vs `cors`/`same-origin`) before treating a same-origin GET as a document navigation — App Router RSC/flight fetches (client `router.push`, `.txt?_rsc=` in static export) share the same path space. Never serve another route's cached HTML as an app shell (embedded RSC payload causes an infinite hard-reload loop). Any new route reached via `router.push` MUST be added to `APP_SHELL_ROUTES`. Keep client-readable params (book, chapter, id) in the search string, not in dynamic `[slug]` segments — a finite app-shell set + `ignoreSearch` then serves everything offline. `ignoreSearch` is safe only when different queries render the same client-parsed RSC route. SW `cache.put` for navigations only when `res.ok && !res.redirected` (a login redirect cached under a route key permanently replaces the app offline).

### Directus: read profiles via admin client; probe external validation for real
**Source**: 2026-07-03-18.17.md, 2026-06-30-23.45.md
**Rule**: Never rely on `/users/me` under a user token for profile fields — the "Чтец" role policy returns only `id`. Server-side profile reads go through the admin client by `directus_id`. Keep auth routes consistent (if two of three do admin-reads, the third must not silently differ). Synthetic emails ALWAYS need a real TLD (dotted domain; `@local`, `.invalid`, `.test` are rejected by Directus v11). When integrating an external service, verify its field validation with a real API probe, not by "the format looks fine".

### Session-sealed data is a cache — design its refresh path
**Source**: 2026-07-04-21.58.md, 2026-06-30-16.46.md
**Rule**: Any DB field copied into the iron-session cookie is a cache; before sealing it, answer "what happens when the source changes?" (provide a refresh path). React default props (`prop = 'fallback'`) only guard `undefined`, not `''`/`null` — pass `value || undefined` for user-facing strings. Calls fired on every page (providers in the root layout) must never hit session-protected endpoints without `skipAuth` — the global 401→redirect hook fires on public routes otherwise.

### Enriching data must not take down the screen
**Source**: 2026-07-03-23.46.md
**Rule**: When a screen is built from several sources, read enriching data (progress, counters) in its own try/catch — one shared `try` around everything means the most fragile source dictates screen availability.

### React perf: memo + stable handlers for large motion lists; no effect-based UI resets
**Source**: 2026-05-08-16.39.md, 2026-04-22-23.24.md
**Rule**: Lists >50 items in carousels/listboxes with motion-values: ALWAYS wrap item components in `React.memo` with an explicit comparator; stabilize handlers passed to memoized children via the ref-pattern (refs updated in useEffect, useCallback with empty deps); keep `useTransform` chains single-level; pulse/snap animations ≤10% amplitude with ease-out, no overshoot easing. `DayNavigationBar` is perf-critical — visual props only. To reset UI state when a modal/sheet closes, unmount the subtree or use keys, not `useEffect` + `setState` on the open flag (React Compiler ESLint forbids it). After edits in client components with hooks, lint the file.

### Measure content-dependent sizes; don't hardcode them
**Source**: 2026-07-09-01.27.md, 2026-07-07-23.51.md
**Rule**: If an element's real size depends on content/font/device (nav bar height, label line-height), the clearance source of truth is the measured size (ResizeObserver → CSS custom property), not a hand-maintained constant. To lift a card above a warm/off-white background, use solid `bg-app-surface` + a pronounced drop shadow (`…-20px rgba(15,23,42,0.30–0.35)`), not a 6% border on a translucent surface (≈2% lightness difference reads flat).

### Static export deployment context
**Source**: 2026-07-10-21.17.md
**Rule**: Production is a static `out/` served with a Serwist SW. Fonts must be self-hosted via `next/font` (build-time, precached); watch the precache budget warning in `scripts/build-sw.ts` (>15MB). A UI "bug" reproducible only on prod is often a stale deployed bundle/SW cache, not the sources.
