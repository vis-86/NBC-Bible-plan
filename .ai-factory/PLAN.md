  источник — `useAutoHideOnScroll` (жест скролла), в `sheets` принудительно `false`.
- `useAutoHideOnScroll` отдаёт наружу ТОЛЬКО `{ hidden, ignoreNextScroll }` — `setHidden` живёт
  внутри (`src/shared/hooks/useAutoHideOnScroll.ts:12`). Программно вернуть шапку нечем, и это ок.
- `SetlistPagerDock` уже подписан на `headerHidden` (`page.tsx:398`), скрытие — классы
  `translate-y-24 opacity-0` на `[data-setlist-pager-dock]`.
- Стек инструментов (`SongToolStack`, `page.tsx:352-365`): FAB автоскролла + карандаш
  (`data-song-ink-open`), прячется только при шторках/режиме пометок.
- Кнопки скорости автоскролла — портал в `body` (`SongAutoScroll.tsx:80-112`), от `SongToolStack`
  не зависят: в фокус-режиме обязаны остаться.
- `ignoreNextScroll` вызывается на КАЖДОМ программном кадре (`useAutoScroll.ts:193`) — автоскролл
  сам по себе состояние `hidden` не двигает.
- Инвариант «стек не прячется вместе с шапкой» задокументирован в трёх местах:
  докблок `SongToolStack.tsx:14-16`, `AGENTS.md:179`, `docs/song-viewer-spec.md:362-365`.
- Поля ридера: `src/features/reading/components/ReadingView.tsx:330` — единственный `px-6`
  в `src/features/reading/**`.

## Явные границы задачи

- Автоскролл прячет только **хром страницы**: шапку, карандаш, таблетку сета.
  Play/pause FAB и кнопки скорости остаются — иначе инструмент нельзя выключить.
- Офлайн-контур не затрагивается (нет новых сетевых путей, IDB-ключей, маршрутов).

  пользователя, автоскроллом НЕ трогаем.

## Tasks

### T1. [x] Фокус-режим: играющий автоскролл сворачивает хром страницы

**Файл:** `src/app/dashboard/song/page.tsx`

- Поднять объявление `autoscroll` (строка 84) выше `headerHidden` (строка 79) — порядок в теле
  компонента важен (TDZ). `ignoreNextScroll` объявлен ещё выше (строка 52), конфликта нет.
- `const headerHidden = mode === 'scroll' && (hidden || autoscroll.playing);`
  Таблетка сета уезжает бесплатно — она уже читает `headerHidden`.
- Карандаш: `<SongInkButton>` рендерить только при `!autoscroll.playing`. FAB `SongAutoScroll`
  остаётся смонтированным всегда — им и выключают режим.
- Комментарием зафиксировать «почему»: во время игры лист едет сам, любой элемент хрома — помеха
  чтению; выход только через FAB, поэтому он единственный не прячется. Вход в режим пометок и так
  гасит автоскролл (`useSongInk.onEnter`), так что скрытый карандаш ничего не отнимает.
- **Обратный переход:** после паузы состоянием шапки владеет жест скролла — вернётся при скролле
  вверх. Никакого программного возврата.
- **Отклонение от плана (по факту реализации):** `setHidden` пришлось отдать наружу из
  `useAutoHideOnScroll`, и старт автоскролла ставит его в `true`. План исходил из того, что
  к моменту стопа жест уже в `hidden=true`, но `ignoreNextScroll` подавляет детекцию
  направления на программных кадрах — жест так и остаётся в `false`. Без правки стоп у низа
  мгновенно возвращал шапку, вьюпорт уменьшался и выталкивал последние строки под фолд
  (поймал существующий e2e-кейс «остановка ровно у низа»). Наружу отдаётся только установка
  в `true`; возврат хрома по-прежнему за жестом.
- **Logging (verbose):** в dev-ветке `console.debug('[SongPage] chrome hidden', { headerHidden, playing: autoscroll.playing })`
  рядом с существующим `[SongPage] view mode`.

### T2. [x] Гистерезис `canScroll`: сворачивание шапки не должно гасить сам автоскролл

**Файл:** `src/features/songs/hooks/useAutoScroll.ts`

Проблема, которую создаёт T1: свёрнутая шапка увеличивает `clientHeight` контейнера. На песне,
которая скроллилась «ровно на высоту шапки», после старта срабатывает стоп у низа
(`scrollTop + clientHeight >= scrollHeight`, строка 198), `ResizeObserver` пересчитывает
`canScrollMeasured` в `false` (строка 144) → FAB уходит из DOM → `playing=false` возвращает
шапку → FAB возвращается. Мигание.

- В `measure` (строка 144) не сбрасывать `canScrollMeasured`, пока идёт проигрывание:
  держать `playing` в ref и при `playingRef.current === true` оставлять предыдущее значение.
  Остановкой по-прежнему владеет только rAF-стоп у низа — семантика §8 не меняется.
- Комментарием объяснить причину (рост `clientHeight` от скрытого хрома — не «контента не стало»).
- **Logging (verbose):** в существующий `debug()` добавить причину замера
  (`debug('canScroll', { measured, playing })`), чтобы мигание было видно в консоли.
- Зависимость: делать вместе с T1 — по отдельности T1 даёт регресс.
