# Дизайн-система

Справочник для волонтёра, который добавляет новый экран или компонент. Токены живут в
`src/app/globals.css` (`@theme inline`), примитивы — в `src/shared/components/ui/`.

## Шрифты

Три семейства через `next/font/google` (`src/app/layout.tsx`), self-hosted (обязательно
для static export + Serwist precache):

| Шрифт | CSS-переменная | Utility-класс | Где используется |
|-------|-----------------|---------------|-------------------|
| Inter | `--font-inter` | `font-sans` (default) | UI: кнопки, заголовки, формы |
| Literata | `--font-literata` | `font-serif` | Длинное чтение: текст Библии, тексты песен |
| Geist Mono | `--font-geist-mono` | `font-mono` | Аккорды и цифры (моноширинное выравнивание) |

Добавляя новый экран — не задавайте `font-family` вручную, используйте `font-sans`
(по умолчанию на `<body>`) или `font-serif` для контентных блоков длинного чтения.

## Токены

Все цвета, радиусы и тени — CSS-переменные с префиксом `--app-*` в `globals.css`,
промаппленные в Tailwind-утилиты через `@theme inline`. Не хардкодьте цвета
(`bg-gray-100`, `#fff` и т.п.) — только токены. Утилиты также собраны как строки
в `src/shared/config/design-tokens.ts` (`tokens.bg`, `tokens.text`, `tokens.radius`, …)
для типобезопасного импорта.

### Радиусы (`rounded-app-*`)

Правило вложенности: внутренний элемент **строго меньше** радиуса родителя.

| Утилита | Значение | Типичное применение |
|---------|----------|----------------------|
| `rounded-app-sm` | 8px | Мелкие контролы: nav-кнопки, иконки-кнопки |
| `rounded-app-md` | 12px (базовый) | Карточки списков, выбираемые строки, инпуты |
| `rounded-app-lg` | 16px | CTA-баннеры, крупные иконки-плашки |
| `rounded-app-xl` | 24px | Крупные карточки-секции |
| `rounded-app-card` | 28px | Самые крупные карточки-«герои» (см. `TodayReadingCard`) |

### Тени (`shadow-app-*`)

`shadow-app-sm` / `shadow-app-md` / `shadow-app-card` — мягкие многослойные тени
(две полупрозрачные тени вместо одной жёсткой), отдельные значения для light/dark
(в dark чёрные тени малоразличимы на тёмном фоне — акцент на подъём через
`bg-app-surface-elevated`, а не через shadow).

### Контраст текста

`text-app-text-muted` (вспомогательный текст) подобран под AA (≥4.5:1 на
`bg-app-bg`/`bg-app-surface` в обеих темах). `text-app-text-subtle` — **декоративный
маркер** (disabled-состояния, `aria-hidden`), не для основного текста — его контраст
ниже порога специально.

## Примитивы (`src/shared/components/ui/`)

- **`Button`** — варианты `primary`/`secondary`/`ghost`/`inverse`/`danger`, размеры
  `sm`/`md`/`lg` (md/lg ≥44px по высоте — Fitts), pill-форма (`rounded-full`),
  press-отклик (`active:scale-[0.97]`), `focus-visible` ring.
- **`Card`** — варианты `surface`/`elevated`, `rounded-app-card`, разделение тоном
  фона вместо жёсткой рамки.
- **`PageHeader`** (`src/shared/components/layout/`) — единая шапка экрана,
  `variant="page"` (top-level таб) / `variant="view"` (экран с «назад»). У `view`
  есть `density="compact"` (по умолчанию `"default"`) — «шапка режима чтения»:
  ниже (`min-h-[52px]`), без тени, заголовок `text-[15px]`, паритет с `ReadingHeader`;
  используется на экране песни. НЕ используйте `PageHeader` для: `ReadingHeader`
  (независимая тема ридера light/dark/sepia), `SongView`-контент-хедера (заголовок
  песни внутри `<article>`, не шапка страницы), greeting-хедера `PlanView`
  (прозрачный editorial-блок, бровь красится отдельно — см. комментарий в
  `PageHeader.tsx`).
- **`RangeSlider`** (`src/shared/components/ui/RangeSlider.tsx`) — обёртка над
  `<input type="range">` с интерактивной высотой 44px (`min-h-11`) и тумбом 28px;
  визуальный трек тоньше (6px), но тап-зона не уменьшается вместе с ним. Трек/тумб
  описаны в `globals.css` под классом `.app-range` (псевдоэлементы
  `::-webkit-slider-*`/`::-moz-range-*` не стилизуются Tailwind-утилитами). Единая
  точка для всех слайдеров приложения (размер шрифта песни/ридера, межстрочный
  интервал, полутона/каподастр).
- **`ActionMenu`** (`src/shared/components/ui/ActionMenu.tsx`) — kebab-меню
  (вертикальное многоточие 44×44) со списком действий над объектом: `items`
  (`{ id, label, icon?, destructive?, onSelect }`) + `ariaLabel` триггера.
  Так оформляются второстепенные действия карточки — по одной иконке на действие
  прямо в карточке шапка захламляется, и с ростом числа действий это не масштабируется.
  Панель рендерится **порталом** в `body` с `position: fixed`: карточки списков
  живут под `overflow-hidden`, внутри потока меню было бы срезано скруглением.
  Плата за портал — привязка к координатам триггера: скролл и resize меню закрывают,
  а не догоняют. Раскрывается вниз, а у нижней кромки экрана — вверх. Закрытие:
  выбор пункта, тап мимо, Escape (с возвратом фокуса на триггер).
  Разрушающий пункт — `destructive: true` (красный текст), само подтверждение —
  на стороне вызывающего экрана, меню ничего не спрашивает.

Прежде чем писать новый `<button>`/карточку с нуля — проверьте, не решает ли задачу
`Button`/`Card`.

## Тач-таргеты

Каждый интерактивный элемент — ≥44×44px область клика (не обязательно визуальный
размер: используйте padding/hit-area трюк, как в `SearchBar` clear-кнопке или
переключателях в `ReadingSettingsForm` — маленький визуальный track внутри
увеличенной прозрачной кнопки). Иконки-кнопки без видимого текста — обязателен
`aria-label`.

Правило распространяется и на слайдеры: визуальный трек может быть тоньше 44px
(`RangeSlider` — 6px), но интерактивная зона (обёртка + `input`) обязана оставаться
≥44px по высоте. Тонкий трек — не повод сузить тап-зону вместе с ним.

## Скроллбар скрыт глобально

`globals.css`: `html { scrollbar-width: none }` + `*::-webkit-scrollbar { display: none }`.
Приложение — PWA с мобильным поведением на всех ширинах, и полоса прокрутки на десктопе
выбивается из раскладки. Сама прокрутка (колесо, тачпад, клавиатура) не затрагивается.
Плата: на десктопе исчезает единственный визуальный признак «здесь есть скролл» — длинные
списки обязаны обрывать контент видимо (частично видимая карточка/строка у нижней кромки),
а не заканчиваться ровно по границе контейнера. Локальные классы `.no-scrollbar` /
`.hide-scrollbar` остались легаси и ничего больше не добавляют.

## Шапка экрана: back + заголовок + максимум 2 действия

Правило для `PageHeader`/кастомных шапок (`ReadingHeader`, шапка песни): справа —
не больше двух интерактивных действий (например тональность + настройки). Всё,
что не помещается — счётчик позиции, листание, вспомогательные инструменты —
уезжает вниз экрана (нижний док/стек), а не копится в шапке. На узком экране
(375px) переполнение шапки — баг, не «сожмём шрифт».

## Свайп между экранами: `SwipePager` / `PagerHint`

`src/shared/components/pager/SwipePager.tsx` + `PagerHint.tsx` — общие примитивы
горизонтального свайпа между «страницами» одного типа (песни сета, главы
Писания). Контракт (`SwipePagerProps`/`PagerHintProps`) — см. код, он стабилен и
не должен обрастать частными пропами под конкретный экран.

- **Свайп обязан вызывать те же функции, что видимые кнопки ‹ ›** (`onPrev`/
  `onNext` = ровно те же обработчики, что у кнопки). Разошедшиеся пути
  «кнопка ≠ жест» — уже разбиравшийся класс багов в проекте.
- Видимые ‹ › остаются всегда — свайп дополняет, не заменяет: `SetlistPagerDock`
  в песне, `FloatingChapterNav` в ридере.
- Край экрана (24px) — системному back-свайпу; `SwipePager` использует общий
  `resolveSwipeDirection` (`useHorizontalSwipe.ts`), не копирует пороги.
- **Тянем не страницу, а её отклик.** Контент во время жеста сдвигается
  максимум на 20px (10px на границе) — резиновой функцией `shiftForDelta`,
  а не 1:1 за пальцем: экран не должен разъезжаться. Сдвигается только
  внутренний узел `[data-swipe-pager-content]`.
- `PagerHint` — индикатор «N из M», не контрол: `pointer-events: none`,
  `aria-hidden`. Тёмная нейтральная плашка без пропа темы — обязана читаться
  поверх любой темы приложения/ридера.
- **Край краю рознь.** Экран описывает цель жеста объектом
  `PagerHintTarget { index, label, atEdge, action? }`:
  - `action: 'end'` — дальше не переход, а терминальное действие (ридер в режиме
    плана: свайп за последнюю главу дня завершает день через `SwipePager.onEnd`).
    Подсказка показывает ✓ «Завершить», без «N из M»;
  - `atEdge` без `action` — мёртвый край, идти некуда: подсказки **нет вовсе**
    (`PagerHint` возвращает `null`). Обещать переход, которого не будет, вреднее,
    чем не показать ничего;
  - иначе — обычная «N из M» с подписью.

  Считает это вызывающий экран, а не пейджер: `SwipeDragState.atEdge` считает
  наличие `onEnd` отсутствием края и на «Завершить» не годится.
- **Подсказка неподвижна и следует прогрессу.** Она передаётся пропом
  `overlay` (вне сдвигаемого узла) и стоит по центру, как бы далеко ни ушёл
  палец. Непрозрачность = прогресс жеста: `SwipePager` пишет
  `--swipe-progress` (0…1, единица ровно на пороге перехода — 60px, тот же,
  что у `resolveSwipeDirection`), `PagerHint` читает переменную в `opacity`.
  Отпустили, не дойдя до порога — прогресс гаснет вместе с возвратом страницы,
  и НИЧЕГО не происходит; дошли (подсказка полная) — отпускание = переход,
  после которого подсказка коротко вспыхивает (`showAndHide`).
  Во время жеста экран вызывает `track()` — только содержимое подсказки;
  форсировать `visible` в drag'е нельзя (вспыхнет на первых же 8px).
  Прогресс идёт CSS-переменной, а не React-стейтом: иначе страница песни
  перерисовывалась бы на каждый `pointermove`.
- **Одна ось — одно значение.** Вертикаль экрана = продвижение внутри контента
  (скролл текста / стопка листов), горизонталь = переход между «страницами»
  соседнего уровня. Предикат для свайпа — `mode !== 'paged'`:

  | Режим песни | Вертикаль | Горизонталь свободна? |
  |---|---|---|
  | `scroll` (1 колонка) | скролл текста | да — свайп работает |
  | `sheets` (2 колонки, планшет) | листы стопкой | да — свайп работает |
  | `paged` | — | **нет** — страницы лежат вбок (`flow.scrollLeft`), свайп между песнями выключен (кнопки/док остаются) |

  Единственная широкая раскладка — узкая и планшетная шапка/док/стек одинаковы;
  отдельной раскладки под ширину нет (переполнение — проблема только 375px).

## Правый нижний край песни — `SongToolStack`

`src/features/songs/components/SongToolStack.tsx` — единая точка входа для
инструментов экрана песни (сейчас автоскролл; карандаш заметок M10 сюда же).
Вертикальная колонка, растёт **вверх**, горизонтальный бюджет фиксирован
(48px + поле) независимо от числа слотов. **Активный инструмент забирает
правый край целиком, остальные слоты в это время скрыты** — правило для
будущей палитры инструментов, не только автоскролла. Нижняя таблетка
навигации сета (`SetlistPagerDock`) правый край не занимает — он весь у стека.

Стек **не** скрывается вместе с шапкой при скролле (в отличие от
`SetlistPagerDock`): автоскролл включают именно во время чтения, и уезжающая на
первом движении листа кнопка делала бы инструмент недоступным. Прячут стек
только открытые шторки — условием рендера на стороне экрана песни.

## Анимация

Дисциплина: только `transform`/`opacity` (никаких `width`/`height`/`top` — не
триггерят layout, честные 60fps). Entrance — fade+rise (`opacity: 0, y: 8 → 1, 0`),
easing out-expo (`cubic-bezier(0.16, 1, 0.3, 1)`), ≤250ms, каскад ≤3 элементов
(пример: три карточки дашборда в `PlanView`). Press-отклик — `active:scale-[0.97]`
(CSS) или `whileTap={{ scale: 0.97 }}` (`motion`-компоненты).

`prefers-reduced-motion` уважается **везде**: `useReducedMotion()` из `motion/react`
для motion-компонентов, `@media (prefers-reduced-motion: reduce)` для CSS-keyframes.
Не удаляйте существующие гарды.

**Исключение — `DayNavigationBar`:** perf-critical компонент (React.memo +
`useTransform` на scroll position). Меняйте там только визуальные пропсы (цвета,
радиусы) — не трогайте wiring мемоизации/трансформов.
