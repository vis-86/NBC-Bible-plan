# Настройка хранения истории чата с ИИ

Этот документ описывает, как настроить хранение истории переписки пользователей с ИИ-наставниками в Directus.

## 1. Создание коллекции `chat_history` в Directus

### Шаг 1: Создание коллекции

1. Зайдите в Directus Admin Panel
2. Перейдите в **Settings** → **Data Model**
3. Нажмите **Create Collection**
4. Введите название: `chat_history`
5. Выберите тип: **Standard Collection**
6. Нажмите **Continue**

### Шаг 2: Добавление полей

Добавьте следующие поля в коллекцию:

#### Поле `id` (автоматически создается)
- Тип: **Integer**
- Primary Key: ✅
- Auto Increment: ✅

#### Поле `directus_user_id`
- **Field Key**: `directus_user_id`
- **Type**: **UUID**
- **Required**: ✅
- **Interface**: **Input**
- **Note**: UUID пользователя Directus

#### Поле `pastor_id`
- **Field Key**: `pastor_id`
- **Type**: **String**
- **Required**: ✅
- **Interface**: **Select Dropdown**
- **Options**: 
  - `THEOLOGIAN` - Богослов
  - `PRACTICAL` - Практик
  - `COMFORTER` - Утешитель
  - `HISTORIAN` - Историк
- **Note**: ID выбранного пастора (наставника)

#### Поле `messages`
- **Field Key**: `messages`
- **Type**: **JSON**
- **Required**: ✅
- **Interface**: **Input Code** (JSON)
- **Note**: Массив сообщений чата в формате:
  ```json
  [
    {
      "id": "string",
      "role": "user" | "model",
      "text": "string",
      "timestamp": 1234567890
    }
  ]
  ```

#### Поля `created_at` и `updated_at` (автоматически создаются)
- Эти поля создаются автоматически при включении **Timestamps** в настройках коллекции

### Шаг 3: Настройка прав доступа

1. Перейдите в **Settings** → **Roles & Permissions**
2. Выберите роль **Public** (или нужную роль)
3. Для коллекции `chat_history`:
   - **Read**: ✅ (только свои записи)
   - **Create**: ✅ (создание своих записей)
   - **Update**: ✅ (обновление своих записей)
   - **Delete**: ✅ (удаление своих записей)

**Важно**: В приложении используется admin API, поэтому права доступа для обычных пользователей не критичны, но лучше настроить для безопасности.

### Шаг 4: Настройка фильтров (опционально)

Если хотите, чтобы пользователи видели только свои записи:

1. В настройках роли для `chat_history`
2. В разделе **Permissions** → **Read**
3. Добавьте фильтр:
   ```
   {
     "directus_user_id": {
       "_eq": "$CURRENT_USER"
     }
   }
   ```

## 2. Проверка работы

После создания коллекции:

1. Убедитесь, что коллекция видна в **Content** → **chat_history**
2. Проверьте, что поля имеют правильные типы
3. Попробуйте создать тестовую запись через API или админ-панель

## 3. Структура данных

```json

```

## 4. API Endpoints

После настройки коллекции доступны следующие endpoints:

- `GET /api/chat/history?pastor_id=THEOLOGIAN` - получить историю чата
- `POST /api/chat/history` - сохранить историю чата
- `DELETE /api/chat/history?pastor_id=THEOLOGIAN` - очистить историю чата

Все endpoints требуют аутентификации через сессию.

## 5. Особенности реализации

- **Одна запись на пользователя и пастора**: Для каждой пары (пользователь, пастор) хранится одна запись
- **Автоматическое обновление**: При отправке нового сообщения обновляется массив `messages`
- **Автоматическая загрузка**: История загружается при открытии чата с конкретным пастором
- **Очистка**: При нажатии кнопки "Очистить" удаляется запись из базы данных

## 6. Миграция существующих данных

Если у вас уже есть пользователи с историей чата (хранящейся в другом месте), можно создать скрипт миграции для переноса данных в новую коллекцию.
