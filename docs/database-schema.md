# Схема базы данных Directus (SQLite)

Этот документ содержит описание структуры таблиц, используемых в приложении Bible Plan.

## Основные таблицы

### 1. `plan` — График чтения
Хранит информацию о том, что и в какой день нужно читать. Каждая глава хранится отдельной записью.
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER | Первичный ключ |
| `numbers` | INTEGER | Порядковый номер дня |
| `day` | TEXT | Дата в формате DD.MM.YYYY |
| `read` | TEXT | Текст одной главы (например, "Быт. 1") |
| `item` | INTEGER | Порядковый номер главы внутри дня (1, 2, 3...) |

**Пример данных:**
| numbers | day | read | item |
| :--- | :--- | :--- | :--- |
| 353 | 19.12.2025 | Езд. 4 | 1 |
| 353 | 19.12.2025 | Езд. 5 | 2 |
| 353 | 19.12.2025 | Пс. 136 | 5 |

### 2. `reading` — Прогресс чтения
Фиксирует, какие дни были прочитаны пользователями.
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER | Первичный ключ |
| `user_id` | INTEGER | ID пользователя (из Telegram или системы) |
| `day` | INTEGER | Номер дня из таблицы `plan.numbers` |
| `directus_user_id` | TEXT | UUID пользователя Directus (опционально) |
| `count` | INTEGER | Количество последовательно прочитанных глав. `NULL` = весь день прочитан |
| `completed_items` | JSON | Массив номеров прочитанных глав (например, `[1, 3, 5]`) |
| `year` | INTEGER | Год, к которому относится прогресс (например, 2025, 2026) |

**Логика поля `count`:**
- `count = NULL` — весь день прочитан (совместимо с Python-ботом)
- `count = N` — максимальный последовательный номер прочитанной главы (для обратной совместимости)
- `count = 0` — запись удаляется (ничего не прочитано)

**Логика поля `completed_items`:**
- `completed_items = NULL` — весь день прочитан или используется старая логика
- `completed_items = [1, 3, 5]` — прочитаны главы с номерами 1, 3 и 5 (не обязательно по порядку)
- Позволяет отмечать главы в любом порядке, не требуя последовательного чтения

**Логика поля `year`:**
- Автоматически устанавливается при создании/обновлении записи на текущий год
- Используется для фильтрации прогресса по годам
- Каждый новый год (1 января) план начинается сначала
- При запросах прогресса по умолчанию возвращаются только записи текущего года
- Позволяет группировать пропущенные дни по годам в интерфейсе

### 3. `weeks` — Группировка по неделям
Используется для организации дней в недельные блоки.
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `num_1` ... `num_7` | INTEGER | Номера дней (`numbers` из `plan`), входящих в неделю |

## Вспомогательные и архивные таблицы

### 4. `users` — Пользователи (Telegram)
Связь идентификаторов пользователей и их ников.
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `user_id` | INTEGER | Уникальный ID пользователя |
| `nick` | TEXT | Никнейм пользователя |

### 5. `reminder` — Напоминания
Хранит информацию для рассылки уведомлений.
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `user_id` | INTEGER | ID пользователя |
| `msg_id` | INTEGER | ID последнего отправленного сообщения |

### 6. `plan24` и `weeks23`
Архивные или демонстрационные таблицы с данными за 2023-2024 годы. Структура идентична основным таблицам `plan` и `weeks`.

### 7. `chat_history` — История переписки с ИИ-наставниками
Хранит историю сообщений пользователя с каждым из пасторов (наставников).
| Поле | Тип | Описание |
| :--- | :--- | :--- |
| `id` | INTEGER | Первичный ключ |
| `directus_user_id` | TEXT | UUID пользователя Directus |
| `pastor_id` | TEXT | ID пастора (THEOLOGIAN, PRACTICAL, COMFORTER, HISTORIAN) |
| `messages` | JSON | Массив сообщений чата в формате `[{id, role, text, timestamp}, ...]` |
| `created_at` | TIMESTAMP | Дата создания записи |
| `updated_at` | TIMESTAMP | Дата последнего обновления |

**Структура сообщения:**
- `id`: string — уникальный идентификатор сообщения
- `role`: 'user' | 'model' — роль отправителя
- `text`: string — текст сообщения
- `timestamp`: number — временная метка в миллисекундах

**Логика:**
- Для каждого пользователя и пастора хранится одна запись
- При отправке нового сообщения обновляется массив `messages`
- При смене пастора загружается соответствующая история
